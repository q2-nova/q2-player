# Player specification

Each requirement has a stable ID that code, tests and documents cite. A row
states what the player does and how to check it. Requirements for the image,
kernel and boot are in the
[q2-os specification](https://github.com/q2-nova/q2-os/blob/main/docs/specification.md).
[Not implemented](#not-implemented) lists requirements the player does not
meet yet. `tools/check_docs.py` checks that every ID is defined once and that
every cited ID exists.

Settings keys are in the card's `Q2Mainline/config.toml`. Paths such as
Settings → Playback name the menu rows the listener sees.

## Home and navigation

| ID | Requirement | Acceptance |
| --- | --- | --- |
| HOME-001 | Home lists Set Up Server (only while Navidrome is not set up), Music, Books, Podcasts, Radios, Downloads, Settings, Shuffle Songs, then Now Playing while something is loaded. Books appears when an Audiobookshelf address and token are set, or the card holds a readable local M4B or a downloaded book. Podcasts appears when Audiobookshelf is set up or a downloaded episode is present. Network and sign-in state do not remove either row. | With Audiobookshelf not set up, a local M4B present and no downloaded episode, Home shows Books and no Podcasts. |
| SETTINGS-003 | Settings lists Sound, Playback, Display, Connections, Bluetooth, Storage and System. System lists Clicker, Touchscreen (when the panel exists), Sleep When Idle, Date & Time, then About after a separator. Back returns to the parent row. | Settings shows these seven rows in this order, and About is the last row of System. |
| UX-001 | The UI hierarchy map `tests/ui/ui-hierarchy.md` is generated by replaying the app's own events over generated fixtures: rows, actions, long-Center menus, Now Playing Center cycles and Back targets. The map states its coverage limits. | `implementation_hierarchy_matches_reviewed_map` fails on any hierarchy change until `tests/ui/map.py --write` regenerates the map. |
| UX-002 | A change to the hierarchy carries the regenerated map diff and a short UX rationale. The reference is the iPod: simple lists, few steps on frequent journeys, and long-Center for actions on the selected item. | Each pull request that changes `tests/ui/ui-hierarchy.md` states the UX reason for the change. |
| UX-003 | Core listening journeys stay usable in every release: start music, a book and a podcast, pause, resume, skip and return to the list. A reported failure of a core journey blocks a release even when the technical checks pass. | The headless journeys in `tests/ui` pass for each release candidate. |
| UX-011 | One wheel detent moves one row. In non-alphabetical lists of more than 16 rows, a turn that lasts more than 200 ms accelerates: rows per detent grow with the square of the wheel speed, from 1 to 32. A pause of more than 250 ms or a reversal returns to one row per detent. Lists have no momentum and do not wrap. The curve follows the iPod click wheel and is tuned on the Q2; it is not Apple's algorithm. | In a 500-row list, slow detents move one row each, a sustained fast turn moves several rows per detent, and a 250 ms pause restores one row per detent. |
| UX-012 | In media lists, artwork and text keep a fixed left edge as rows pass the screen's rounded corners. Text-only menus follow the corners. | While an album list scrolls, a title starts at the same x position in every row position. |
| BROWSE-001 | Paged lists load the next page when the selection comes within 4 rows of the loaded end, keep at most 5 pages and keep the selected row by key. No list has a Next page row. Random Albums uses Navidrome's seeded random album API (100 albums per page) on a Navidrome server and the Subsonic random list on other servers. | Scrolling past the end of Random Albums on Navidrome loads further pages with no duplicate rows, and scrolling back shows the earlier pages in the same order. |
| BROWSE-002 | In alphabetical lists of at least 100 rows with more than one initial letter, a deliberate fast turn (at least 15 detents over at least 500 ms at 720°/s or more) switches the wheel to letter mode, where 3 detents move one letter. Letter mode stays while the wheel slows or pauses. Lifting off the wheel returns to row selection. | A short burst or a slow correction never enters letter mode; a sustained fast sweep does; after lift the next detent moves one row. |
| TEXT-001 | In text entry, Return closes the editor without saving or changing settings. OK or holding Center submits; the Delete cell removes the last character. The hint reads "Hold Center to save · Return cancels". | Editing a saved field and pressing Return leaves the stored value unchanged. |
| TEXT-002 | Characters missing from Open Sans are drawn from DejaVu Sans, then from monochrome Noto Emoji. Joiners and variation selectors draw with zero width. Fallback fonts are memory-mapped and rasterized per glyph, with bounded caches. | A playlist name with emoji draws the emoji and shows no missing-glyph boxes. |

## Playback

| ID | Requirement | Acceptance |
| --- | --- | --- |
| PLAYBACK-008 | On Now Playing, Center enters seek mode. The wheel moves the position by 1 s per detent, rising on sustained fast turns to the track length / 120 (1 to 60 s). The seek applies after the wheel rests 500 ms or on Center, and the screen returns to volume after 4 s idle. A track change leaves seek mode and discards a pending seek. Seeking stops 1 s before the end; holding Next seeks 5 s at a time and stops 500 ms before the end, so seeking never skips to the next song. | Turning to the end of a song stops 1 s before the end without advancing; a skip during seek returns to volume with no seek applied. |

| PLAYBACK-010 | A streamed song starts once its first bytes arrive and plays while it downloads; the finished file becomes the cached copy. | PLAYBACK-003 | The Now Playing long-Center menu offers Sleep Timer (Off, 5, 10, 15, 30, 45, 60, 90 or 120 minutes) for books, podcasts, music and radio. The last 10 s fade out; Play during the fade restarts the timer. At expiry playback pauses and seekable items rewind 15 s. The automatic timer arms only for spoken playback that starts inside, or is playing when the clock enters, the local window `[playback] auto_sleep_start` to `auto_sleep_end`, including windows that span midnight. A cancelled automatic timer does not rearm until playback stops, the selection changes or the window ends. | With Duration 30 minutes and the window 22:00 to 07:00, a book started at 23:00 arms a 30-minute timer; at expiry audio fades, pauses and resumes 15 s earlier. |
| PLAYBACK-004 | While a sleep timer runs, Now Playing shows "Sleep in M:SS" (H:MM:SS from one hour) above the artwork, rounded up to the next second. | PLAYBACK-005 | Settings → Playback has no manual Sleep Timer row. Its first row, Auto Sleep Timer, opens one page with Duration (`[playback] auto_sleep_minutes`, default Off), Auto Timer Starts (`auto_sleep_start`, default 22:00) and Auto Timer Ends (`auto_sleep_end`, default 07:00), in 30-minute steps. | Settings → Playback → Auto Sleep Timer lists Duration, Auto Timer Starts and Auto Timer Ends. |
| SETTINGS-001 | Settings → Playback lists Auto Sleep Timer, Gapless, Pause on Unplug, Song Ratings; then Default Spoken Speed, Book Skip Buttons, Skip Forward, Skip Backward; then Streaming Quality, Download Quality, Navidrome Scrobbles, ListenBrainz, Last.fm and Sync Queue, with a separator between the groups. | SETTINGS-002 | Shuffle and Repeat are not in Settings. For music they are rows of the Now Playing long-Center menu (Shuffle: Songs or Off; Repeat: Off, All or One). Shuffle does not apply to a queue with spoken items. | The music Now Playing menu lists Shuffle and Repeat, and Settings → Playback lists neither. |
| RECOVERY-001 | A bad file descriptor during playback (EBADF or EBADFD) reopens the playback resources without changing the queue or position, at most twice per episode; the count resets after 5 s of output. The listener sees "Playback was interrupted", never the error text. Telemetry records the errno and whether recovery succeeded. | An injected EBADF resumes audio at the same track and position and emits one recovery report; a third failure in the same episode stops with "Playback was interrupted". |

## Audio and sound

| ID | Requirement | Acceptance |
| --- | --- | --- |
| AUDIO-001 | The spoken position checkpoint is saved every 30 s by a separate persistence owner that holds one pending save; card sync never runs on the PCM feeder. | Audiobook playback has no output gap at the checkpoint when the card's sync is slow. |
| AUDIO-002 | Pausing a book or podcast keeps the decoder, the stream reader and the unheard PCM until different content plays; Play resumes from them without refetching. A seek, a track change or other content discards them. Audiobook range prefetch is bounded to 4 MiB and keeps a pending response across pause. | After a long pause with the network unavailable, Play resumes from the retained audio without reopening the source. |
| AUDIO-003 | Spoken speed changes tempo without changing pitch. At 100 % the stretcher is bypassed; above 2× two stages are composed. Volume is applied after the stretcher. | At 2.5×, a test tone keeps its frequency and the output has no repeated or dropped periods at stage boundaries. |
| AUDIO-004 | At a track boundary where the sample rate, channel count or sample width changes, the player drains the previous track, closes the PCM, applies volume and Headphone Power with the PCM closed, then opens the new PCM. Output stays muted until it is open. | A FLAC-to-MP3 transition has no transient at the new track's onset in a digital capture. |
| AUDIO-005 | The time from selecting a streamed song to first output is measured as `music-play-to-audio`, from the play request to the first frames the output accepts, with a target in `docs/ux-budgets.json`. | The p90 of `music-play-to-audio` is at or under its target. |
| AUDIO-006 | Settings → Sound → Headphone Power (`[playback] headphone_power`) offers Efficient (default, 0.5 Vrms on fixed rails), Standard (1 Vrms), High (1.73 Vrms) and Maximum (2 Vrms, the stock level). Efficient keeps the installed loudness curve and attenuates at least 1 dB. A level is written only with the headphone PCM closed; a change made while playing applies at the next pause. A driver without the `HP Full Scale` control falls back to Standard or High and logs it. | Each level reads back on all four DACs before playback, and every level can be selected again after another. |
| AUDIO-007 | Volume changes on the headphone jack are smooth: codec attenuation and PCM gain move together, queued PCM follows the codec step, and new PCM continues from that level, so neither stage overshoots. Gain ramps move at most 1 dB per millisecond. Each analog volume write is recorded as an `AnalogVolume` UX mark. | On the 3.5 mm output, single steps and fast direction changes show no interruption or transient and settle at the requested level. |
| AUDIO-008 | On the headphone jack the volume is divided between CS43131 attenuation (half-dB steps) and PCM gain. The codec step keeps headroom for ReplayGain and for the peak of queued audio, and the PCM gain makes up the difference, so the level heard is the level requested. EQ and ReplayGain stay in software. The division does not apply to Bluetooth absolute volume or USB output. | With EQ and positive ReplayGain on, each volume step changes the output level by one step and queued audio does not clip. |
| SPEAKER-001 | The buzzer plays no music. It sounds interaction clicks only: a click for a wheel detent or Center press, and a pitched click on EQ Curves that follows the cursor's frequency. Settings → System → Clicker (`[display] clicker`, default On) turns them off. | With Clicker On, wheel and Center clicks sound and no playback route opens the buzzer. |
| EQ-OUTPUT-001 | The jack uses the headphone profile pinned in Settings → Sound → Equalizer. Each Bluetooth device has its own profile, matched at its first connection from the packaged AutoEQ catalog by name, Device ID and class of device, or chosen by the listener, and kept per device. The EQ switches with the route; the graphic EQ is shared. Equalizer shows the output, the profile and its reason (Pinned, Matched automatically, Chosen, No automatic match) and offers Match Automatically. | Connecting headphones whose name matches a catalog model applies that profile with "Matched automatically"; disconnecting returns the jack's profile. |
| EQ-CUSTOM-STUDIO-001 | The headphone catalog includes the four Beyerdynamic Custom Studio switch positions, packaged from a pinned AutoEq revision with their license. Their low and high shelf filters load as LSC and HSC. | Choose Headphones lists the four positions, and each loads and stays selected as the jack's profile. |
| RESOURCES-001 | On the Q2 the fonts and the AutoEQ catalog are read at run time from `/usr/share/q2nd/fonts` and `/usr/share/q2nd/autoeq`, with bounded reads of regular files and MD5-checked catalog files. A missing catalog shows "Headphone resources are unavailable; restore the packaged files". Fonts are embedded only in test and browser builds. | A release build contains no font or catalog bytes, and a missing or altered resource gives its error instead of a crash. |
| USB-AUDIO-002 | An inserted USB audio device becomes the playback route, through `plughw` with software volume. A device that fails is skipped until its enumeration changes, and unplugging returns the route to the jack. | With a USB DAC enumerated by `snd-usb-audio`, playback moves to it, and unplugging it resumes on the jack. |

## Bluetooth

[Bluetooth headphones](bluetooth.md) describes the stack, codecs and tests.

| ID | Requirement | Acceptance |
| --- | --- | --- |
| BLUETOOTH-001 | The player streams to Bluetooth headphones over A2DP with its own host stack in `q2nd`. The Bluetooth route uses the same decode, EQ, ReplayGain and volume chain as the jack. An open headphone stream takes the output ahead of USB and the jack; when it closes, the jack returns and playback pauses with the unsent audio kept. | With EQ and ReplayGain on, headphone playback uses the device's EQ, and a disconnect pauses without an error and resumes the kept audio on Play. |
| BLUETOOTH-002 | There is one volume per output ([Volume](bluetooth.md#volume)). With AVRCP absolute volume, the player sets the headphones' volume on connect and on each change, follows their reports on screen, and keeps its samples at unity. Without it, software volume applies and the headphones' volume keys step it. Each paired device keeps its own volume; the jack keeps `[playback] volume`. Volume Limit (`[playback] max_volume`) applies to every output. | Headphone buttons move the on-screen volume, the wheel moves the headphones' level, and each device's volume returns at its next connection. |
| BLUETOOTH-003 | Settings → Bluetooth shows the switch with the controller state (Starting…, Ready, or the failure with Try Again), the paired devices with state, codec and bit rate or last connection, then Pair New Device and Preferred Codec. Each device page offers Connect or Disconnect and Forget This Device…; long-Center opens Bluetooth Details, which shows no addresses. Requests made while the controller starts or is busy wait; each pairing step is bounded. Pair New Device ends any connection attempt and none resumes. Automatic codec order is LDAC, aptX HD, aptX, AAC, SBC; a stream opened with a lesser codec is replaced once by the best common codec before audio starts, and the device page gives the reason ([Requests, timeouts and retries](bluetooth.md#requests-timeouts-and-retries), [Negotiation](bluetooth.md#negotiation)). | A pairing started while the controller starts completes without switching Bluetooth off, and headphones that open SBC while offering AAC end up streaming AAC. |

## Engineering

| ID | Requirement | Acceptance |
| --- | --- | --- |
| ARCH-001 | Library persistence, streaming and account lifecycle, and player queue and output ownership are separate modules, each with its own tests and state machines in `crates/machines`. | Each module's tests run without the others' owners. |
